## Features

- SMART strips (P316M, P304M) are polled through the strip path: one point per outlet (`equipment_type=plug`, `plug_id` = the outlet's reported position, else its index), the strip total only when the strip measures one, energy read through Module.Energy, one batched write per strip. A strip whose parent measures nothing is registered for polling (`measures_energy`). (KASACOLLEC-37)
- An outlet whose energy module python-kasa disabled triggers an in-place reconnect: a new client is built in the background (back-off 60 s doubling to 1 h), swapped into every registry once it has connected, and the old one is closed once no fetch holds it. (KASACOLLEC-144)
- harness/fake_smart.py: a stdlib-only KLAP v2 emulator (UDP 20002 discovery, handshake, AES-128-CBC requests, multipleRequest, control_child), run in e2e as a P316M and, with KASA_FAKE_PROTOCOL=iot, as an HS300 behind KLAP. (KASACOLLEC-10)

## Refactors

- `Poller` takes a `ClientRegistry` (the DeviceManager): `is_current`, `connect_fresh`, `swap_client`; fetches of replaced clients are skipped and every client the registry drops goes through `release_client` = `Poller.close_when_free`.
- app/storage/sysinfo_fields.py: one InfluxDB type per sysinfo key; coordinates, ssid and bssid are never written, cached, logged or filed.

## Schema / Migrations

- None (no database migrations). InfluxDB: sysinfo fields keep the types existing devices already wrote; `latitude`/`longitude`/`latitude_i`/`longitude_i`, `ssid` and `bssid` are no longer written to `sysinfo` (additive in effect: the series simply stop).

## Infra / Ops

- **Behaviour change, credentials:** under the default KASA_COLLECTOR_TRUST_DISCOVERED_DEVICES=True, an unlisted device is now logged in to only over KLAP or XOR. AES-login devices (EP25, older KP125M/P110 firmware, KS205/225/240, L5xx, SMART cameras, HTTPS hubs) must be listed in KASA_COLLECTOR_DEVICE_HOSTS to be collected; each is named once in a log warning. (KASACOLLEC-130, -142)
- **Behaviour change, health check:** KASA_COLLECTOR_HEALTH_CHECK_MAX_AGE defaults to max(120, 2 x DATA_FETCH_INTERVAL); a lower setting is raised to that floor with a warning. (KASACOLLEC-137)
- Guards: luxarch 0.325.0 -> 0.344.0, luxlint 0.70.0 -> 0.74.0, luxaudit 0.15.0 -> 0.16.0; compose services ranked for the OOM killer; heavy guard/test runs memory-capped.
- The rebuilt image clears CVE-2026-109518 (apt), the fixable HIGH on 2026.10.5 (KASACOLLEC-129).

## Fixes

- KasaAPI.get_device re-classes a KLAP IOT strip found via discover_single (it was stored as one plug), closes a client it gives up on (failed or cancelled connect), and bounds its own DNS lookup at 5 s.
- A pruned device's client is closed; a moved host's old client is never closed under a running poll.
- Per-device read deadline (80 % of the interval) and a fresh write budget; python-kasa's own timeouts keep their message; a strip is one batch.
- Log redactor: more secret forms (repr beside a quote, bytes repr, JSON of each, uppercase percent escapes), session tokens by key (token=, stok=, 'token': '…'), a field walk that never loses the line, linear key collision naming.
- The legacy-unit emeter path rounds through the base type.
