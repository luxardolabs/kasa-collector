## Features

- **Credential gating** (`app/collector/device_manager.py`, `app/collector/kasa_api.py`). Discovery enumerates without credentials; credentials are then handed only to a device listed in `KASA_COLLECTOR_DEVICE_HOSTS` (by its resolved address too), or to every responder when the new `KASA_COLLECTOR_TRUST_DISCOVERED_DEVICES` is set. `reclaim_retired_devices` honours the same gate. A new unlisted device that needs credentials is logged once and left unauthenticated. (KASACOLLEC-99)
- **Log redaction** (`app/main.py`). `configure_app_logging` installs a redactor scrubbing the configured TP-Link username, password, md5(password), the InfluxDB token and any password embedded in the InfluxDB URL from every line; a handler filter scrubs every run of 32+ hex digits from `kasa.transports.*` records. The startup dump shows `****` for a set secret — no characters, no length. (KASACOLLEC-94, -102)
- **SMART energy fields** — SMART devices write `today_wh` and `month_wh` from python-kasa's Energy module. (KASACOLLEC-105)
- **Harness** — `KASA_FAKE_OUTLET_ALIAS` (every outlet one name) and `KASA_FAKE_LEGACY_UNITS` (HS110 hw v1 float units); the e2e roster grew to seven fakes, including a twin-outlet strip and a legacy-units plug. (KASACOLLEC-90, -95, -96)

## Refactors

- The strip emeter path reads the parent and every outlet, converting each reading, before any point is written; an outlet that does not answer is one counted failure, never a partial or duplicated write, and the whole strip is never retried. (KASACOLLEC-98)
- One `device_id_of()` reads a device's id the same way everywhere (IOT `deviceId`, SMART `device_id`); the poller carries it from the device as polled, so emeter and sysinfo points share it from the first cycle. (KASACOLLEC-104)
- `emeter_fields()` converts legacy IOT units through `EmeterStatus` and drops a value InfluxDB cannot hold (NaN, infinity, an integer outside int64) per field. (KASACOLLEC-95, -98)

## Schema / Migrations

No relational database. **InfluxDB field/tag shape CHANGES this release — read before deploying.** No data is deleted or rewritten; these affect new points going forward:

- Legacy-firmware IOT plugs (e.g. HS110 hardware v1) now write `current_ma` / `voltage_mv` / `power_mw` / `total_wh` instead of the old `current` / `voltage` / `power` / `total`, so they begin appearing on the dashboards. Points written before this release keep the old field names.
- SMART devices add `today_wh` and `month_wh` fields.
- `sysinfo` and `sysinfo_child` points now carry the device's real `device_id` tag instead of `unknown` — a series-key change; earlier points keep `device_id=unknown`.
- Strip outlet points are tagged `plug_id` by the outlet's position (matching `sysinfo_child`) and the strip's `device_id`; outlets sharing a name now land in separate series instead of one.

## Fixes

- **The startup log leaked part of a secret.** A 9–12-character password or token was shown as its first four and last four characters; now `****`, with the InfluxDB URL's credentials stripped and every log line scrubbed. (KASACOLLEC-94)
- **Discovery broadcast the account credentials to any responder, and reclaim handed them to a self-promoted address.** Now only a listed or trusted device is authenticated. (KASACOLLEC-99)
- **python-kasa's KLAP handshake hex was logged at DEBUG**, allowing an offline password guess; scrubbed. (KASACOLLEC-102)
- **Legacy-unit plugs stored 0 for a sub-amp current and floored kilowatt-hours**; now written in milli-units. (KASACOLLEC-95)
- **Strip outlets sharing a name, or polled before the first sysinfo, merged into one series**; each outlet now keeps its own. (KASACOLLEC-96, -97)
- **A bad device reading was reported as an InfluxDB write failure** in the metrics and log; now a device failure. (KASACOLLEC-98)
- **Per-device dashboard tiles blended a strip's total with its outlets**; they now read only the device's own point. Code shipped; KASACOLLEC-39 stays open for the GitHub reply.
