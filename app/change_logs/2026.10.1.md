## Features

- **Fleet logging** (`app/core/logging_config.py`, the emitted `luxarch --emit logging` asset v6). `app/main.py` `configure_app_logging()` installs it once in `__main__`. Every line is one JSON object on stdout (`timestamp`, `level`, `logger`, `message`, `service`, `version`, code location, caller fields under `attributes`); `LOG_FORMAT=text` for local runs; `LOG_LEVEL` / `LOG_MODULE_LEVELS` at runtime. The `KASA_COLLECTOR_LOG_LEVEL_*` settings become per-logger levels (`KasaCollector`, `KasaAPI`, `KasaCompat`, `InfluxDBStorage`); `kasa` (python-kasa) is held at WARNING, as before.
- **`make test` is luxarch's test block.** The Dockerfile gains a `test` stage (`FROM base` + the Poetry dev group), rebuilt from source each run as the bare `kasa-collector-test`. The suite runs against a real InfluxDB (`kasa_test_influxdb`, compose profile `test`, tmpfs, no ports) in its own compose project per run, torn down pass or fail. New `tests/test_influx_integration.py` writes through the collector's async client and reads the points back. Branch coverage via coverage.py, ratcheted against `[test].coverage_min` = 54 (`.luxlint.toml`).

## Infra / Ops

**Pre-deploy: none. Post-deploy: pin `TAG=2026.10.1` in `.env.prod`; anyone setting `KASA_COLLECTOR_STRUCTURED_LOGS` can drop it (ignored), and anyone parsing the old colored text log lines should parse JSON or set `LOG_FORMAT=text`.**

- **`make release` rebuilt for multi-arch scanning.** Refuses an already-released `:VERSION` (fail-closed on any registry answer but not-found) or `v$(VERSION)` tagged at another commit; builds amd64+arm64 once, pushed as `:candidate-<commit>`; pulls and scans it once **per platform** (`luxaudit --image-archive`); then `imagetools create`s `:VERSION` + `:latest`, and `:sha-<commit>` only if `dev-deploy` has not already published it. Replaces `release-scan`, which scanned a separate local build.
- **`make release-public`** refuses a dirty tree and a version GHCR already holds, and checks the release notes, the `v$(VERSION)` tag and `gh` auth before the GHCR push.
- **`make dev-deploy` ends with `make smoke`** (the emitted smoke block v5). This collector serves no HTTP, so it probes the `kasa-collector` container: it must run this commit (its `org.opencontainers.image.revision` label) and reach healthy by its own HEALTHCHECK within 180s. It also imports `app.main` and `app.health.check` in the production image with `.env.dev`. A FAIL fails the deploy.
- `make dev-pin` refuses `candidate-*` tags. `scan_candidate` mounts `$(CURDIR)`, not `$(PWD)`.
- **Bundled InfluxDB (dev/demo):** `/etc/influxdb2` now on the named volume `kasa_influxdb_config`. The first start of an existing stack mounts it empty: data is untouched, but `influx` CLI calls inside the container need `--org`/`--token` (docs/troubleshooting.md).
- Every `docker build` names `--load` (luxarch 0.274.2: the shared docker-container builder otherwise writes only cache).
- Guard pins: luxarch 0.249.3 → 0.278.0, luxlint 0.60.1 → 0.63.1, luxaudit 0.13.0 → 0.13.2.
- Dependencies: python-kasa 0.10.2 → 0.11.0.1 (pin `>=0.11.0.1,<0.12.0`); multidict 6.7.1 → 6.9.1 (CVE-2026-104874); coverage 7.16.2 added to the dev group.

## Fixes

- **KLAP-only HS300 strips lost their outlets when found by discovery.** `Discover._get_device_instance()` classes IOT devices from the family table (`IOT.SMARTPLUGSWITCH` → `IotPlug`); the discovered-device path never ran the re-class. On 0.10.2 this was masked: `update()` raised on such a plug and the collector fell back to the connect path, which re-classed it. Measured on the dev stack against three KLAP-only HS300s: before this release one of them wrote outlet points; after it, all three write 6 outlets each.
- **`.jsonl` file sink ignored `KASA_COLLECTOR_WRITE_TO_FILE`.** `_append_to_file` documented the flag but never checked it, so every cycle wrote files (or logged an exception on a read-only mount) with the setting off. Found by the new InfluxDB integration test. Deployments that set it to `True` (the shipped `.env.*` files do) see no change.
- From an adversarial pass on the new release recipe: arm64 shipped unscanned (a plain `docker pull` of the manifest list fetched one platform); `:sha-<commit>` could be re-pointed; `release-public` could publish before failing its notes/tag checks. All fixed before this release ran.
