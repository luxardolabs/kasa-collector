# 2026.11.1 — 2026-11-24

Sysinfo points from IOT devices land again for buckets carried over from 2026.10.x, the bundled Grafana signs in read-only, python-kasa 0.12.0, and the collector waits out a starting InfluxDB.

## Issues Closed

- KASACOLLEC-150 — 2026.11.0 wrote sysinfo `lnk_on` as text, so a bucket written by ≤2026.10.5 (integer) refused every IOT sysinfo point with a 422. `lnk_on` is no longer written (9df5082, after 833b981's integer fix proved wrong for 2026.11.0 buckets).
- KASACOLLEC-154 — The bundled Grafana's datasource carried the InfluxDB operator token. It now signs in as a read-only v1 user `grafana` (655a1b8). Release action below.
- KASACOLLEC-163 — The collector exited (SystemExit 1) when InfluxDB was not yet serving at startup. Its first connect now retries with backoff for up to 60 s (d186de2).
- KASACOLLEC-157 — python-kasa 0.11.0.1 → 0.12.0 (df00a52).
- KASACOLLEC-148 — The dev stack moved to the dev host, reached by name, with no host port. KASACOLLEC-149 was the edge route (infra). KASACOLLEC-151 declares `[dev_host] front = "none"`.
- KASACOLLEC-141 — Adversarial leads from 2026-11-05 settled: a real HS300 was measured against the 12 s read deadline on the dev stack (98.8-99.8% of cycles stored).
- KASACOLLEC-147, -155, -156, -158, -162 — guard bumps to luxarch 0.375.0, luxlint 0.84.0, luxaudit 0.22.0.
- KASACOLLEC-161 — LuxPM backlog audit.

## Features

- `make local-up` / `local-down` / `local-clean` / `local-logs` / `local-ps`: your real devices plus the published InfluxDB and Grafana pair on the machine running make (compose profiles `collector` + `local`, `.env.local`). This is for anyone running from a clone, now that the `bundled` pair is the dev host's (68ed66c).

## Refactors

- `init-dbrp.sh` creates the read-only user `grafana` from GRAFANA_INFLUX_PASSWORD. A failed create (InfluxDB refuses 8-72 characters) is logged and never ends the init, and the password goes as one `--password=` argument (655a1b8).
- The Grafana datasource uses `user: grafana` plus `secureJsonData.password` in place of an `Authorization: Token` header, and is `editable: false`. INFLUX_TOKEN leaves the `x-grafana` environment (655a1b8).
- `InfluxDBStorage.connect()` retries the ping with a doubling delay, capped by KASA_COLLECTOR_MAX_RETRY_DELAY, for CONNECT_WINDOW_SECONDS (60). It then exits with the same banner (d186de2).

## Schema / Migrations

- None. No Alembic. InfluxDB: sysinfo `lnk_on` is in UNWRITTEN_KEYS (9df5082), so buckets holding it as integer (≤2026.10.5) and as text (2026.11.0) both accept the point. Existing series are untouched.

## Infra / Ops

- python-kasa `>=0.12.0,<0.13.0`, locked 0.12.0. 0.12.0 consolidates KLAP/SSL ciphers, stops querying HomeKit on IOT devices, and raises UnsupportedDeviceError on unknown types. app/ uses none of the removed internals. python-kasa #1748 is still open, so `kasa_compat`'s re-class stays (KASACOLLEC-106).
- Every deployed compose service logs through one `x-logging` block: json-file, `max-size` 10m, `max-file` 5, overridable with LOG_DRIVER / LOG_MAX_SIZE / LOG_MAX_FILE (5a94097, repo.compose_logs_bounded).
- The remote `prod-*` targets pass `--project-directory` / `-f` / `--env-file` to compose instead of `cd`-ing first (66033ee).
- Dev stack on the dev host (DEV_HOST := devhost). InfluxDB has a fixed address on `kasa_dev` (KASA_DEV_INFLUX_ADDR, default 10.210.250.10), and the dev Grafana is pinned on `dev-edge` at 172.30.0.15. The dev Grafana refuses an empty, `admin` or placeholder GRAFANA_PASSWORD (`ops/grafana/dev-entrypoint.sh`) (68ed66c, 1ec9131).
- The local and demo pairs publish on 127.0.0.1 by default (GRAFANA_BIND / INFLUX_BIND) (68ed66c).
- New env variable: GRAFANA_INFLUX_PASSWORD (`.env.example`, `.env.demo`).
- Guards: luxarch 0.366.2 → 0.375.0, luxlint 0.79.1 → 0.84.0, luxaudit 0.18.0 → 0.22.0. Hooks, skills and the smoke, test-block and gitleaks blocks were re-emitted; hooks/pre-push was re-emitted for luxlint 0.84.0.

## Fixes

- IOT sysinfo points dropped with a 422 on buckets carried over from 2026.10.x (KASACOLLEC-150, 9df5082).
- The bundled Grafana held the InfluxDB operator token, so any Grafana sign-in could write or delete through the datasource proxy. Against a throwaway pair, main's files gave a write 204 and a whole-bucket delete 204; with the fix, a write 403, a failed delete, and reads 200 (KASACOLLEC-154, 655a1b8).
- The collector restarted on every deploy that recreated InfluxDB beside it. On the dev stack: RestartCount 1 before; after the fix, 0, with a "not answering yet; retrying" warning, then connected (KASACOLLEC-163, d186de2).

### Deploy runbook (2026.11.1)

This repo has no prod deployment: a release ends at the private registry, GHCR, the GitHub Release and the dev stack.

1. [main checkout, build host] `make release` — expect: the multi-arch candidate scanned per platform, then `:2026.11.1` pushed to the private registry. On failure: fix the red it names and rerun (it refuses an already-released VERSION, so a failure before the push is safe to retry).
1. [main checkout, build host] `make release-public` — expect: `:2026.11.1` copied by digest to ghcr.io/luxardolabs/kasa-collector, `:latest` moved to it, then the GitHub Release `v2026.11.1` published from `app/release_notes/2026.11.1.md`. On failure after the copy: `make release-public PUBLIC_RESUME=1`.
1. [main checkout, deploys to the dev host] `make dev-pin TAG=2026.11.1`, then `make smoke` — expect: every line PASS, `kasa-collector runs this commit`. Rollback: `make dev-pin TAG=sha-4b05c73`.
1. [each existing bundled stack, local or dev] KASACOLLEC-154's release action below. The dev stack was done on 2026-11-24. Users of the published image who run the bundled stacks follow the same steps from the release notes.

### Release actions

- KASACOLLEC-154: on each bundled stack (local, demo or dev) whose InfluxDB volume was set up before this release:

  1. Add `GRAFANA_INFLUX_PASSWORD=<8 to 72 characters>` to its env file.
  1. Restart it (`make local-up` / `make demo-up` / `make dev-up`).
  1. Create the read-only user once, reading the password from the container's environment: `docker exec <kasa_local_influxdb|kasa_influxdb> sh -c 'influx v1 auth create --org "$DOCKER_INFLUXDB_INIT_ORG" --token "$DOCKER_INFLUXDB_INIT_ADMIN_TOKEN" --username grafana --password="$GRAFANA_INFLUX_PASSWORD" --read-bucket "$(influx bucket list --org "$DOCKER_INFLUXDB_INIT_ORG" --token "$DOCKER_INFLUXDB_INIT_ADMIN_TOKEN" --name "$DOCKER_INFLUXDB_INIT_BUCKET" --hide-headers | cut -f1)"'`.
  1. Open a dashboard and check that it shows data.

  Until this is done, that stack's dashboards are empty; collection is unaffected. A fresh volume creates the user itself.
