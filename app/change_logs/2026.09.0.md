## Features

- **`app/collector/kasa_compat.py`** — local python-kasa 0.10.2 patches for KLAP-only devices, as a startup shim rather than a vendored fork. Corrects transport selection when a device declares `login_version: 2` (upstream PR #1731) and derives the device class from sysinfo over any transport so a multi-outlet strip is not built as a childless plug (upstream issue #1748). `verify_still_needed()` inspects the installed library at startup and warns when either defect disappears, so an upstream fix reads as "delete this module".
- **`collector_stats` gains `write_failed`** — a device polled successfully whose write to InfluxDB failed is now counted separately from a device that could not be polled. Added as a new field rather than folded into `failed`, so existing dashboard panels keep their meaning.
- **Grafana "Collector Health" row** — `collector_stats` had never been read by any dashboard since it shipped. Both status dashboards now surface devices / succeeded / poll-failed / write-failed / cycle duration, with the two failure panels red above zero.
- **Two discovery knobs** — `KASA_COLLECTOR_DISCOVERY_MISS_THRESHOLD` (default `3`) and `KASA_COLLECTOR_DISCOVERY_CATCH_UP_DELAY` (default `30`). Both documented in `docs/configuration.md` and `.env.example`.
- **`make onboard-check`**, **`make status`**, **`make plan`**, **`make mypy`**, **`make honest`**, **`make guard-upgrade`** targets.
- **`.claude/skills/release/SKILL.md`** — the fleet release ritual, emitted from `luxarch --emit release-skill`, so `/release` runs the same steps every time.

## Refactors

- mypy moved to the mount-only luxlint leg. The previous in-repo tail ran without the app's dependencies, so every `py.typed` library degraded to `Any` and `strict` checked almost nothing.
- Dev-group `ruff`/`mypy`/`types-aiofiles` removed — luxlint runs both tools in its own pinned image, so the copies here were never invoked. Lock 38 → 31 packages.
- `harness/fake_kasa.py` brought under the lint gate and fully typed (11 mypy errors → 0). It was previously first-party Python that no check ever scanned.
- `DeviceContext.__aexit__` typed `Literal[False]` — it has a single `return False` and never suppresses, but the loose `bool` left mypy assuming the block could swallow and fall through.
- Poetry-in-docker made hermetic (`POETRY_VIRTUALENVS_IN_PROJECT=false`); removed the in-repo `.venv`.
- `initialize_manual_devices()` became `reconcile_manual_devices()`, called every discovery cycle rather than once at startup.

## Schema / Migrations

None. No relational database in this service.

`collector_stats` gains the additive `write_failed` field. **The `ip` tag's VALUE changes for manually-configured devices** (KASACOLLEC-64): it previously held the configured hostname and now holds the resolved address. Tag *keys* are unchanged. Because InfluxDB series identity includes every tag, affected devices start new series at this release; the historical series keep their old value and are not backfilled. No dashboard reads the `ip` tag — every panel aggregates by `device_alias`, so old and new series merge into one line and no graph shows a seam. Only an ad-hoc query filtering on `ip` across the boundary needs both values.

## Infra / Ops

- Build backend is hatchling, version derived from `VERSION`; Poetry stays the dependency manager in non-package mode.
- Compose migrated to the fleet standard: ONE `compose.yaml` with the bundled InfluxDB + Grafana as a `bundled` profile, replacing `compose.yml`/`compose.dev.yml`/`compose.prod.yml`. Environments differ only by `.env.<env>`. Compose never builds; the app image is a pinned registry ref.
- `make check` is the byte-identical fleet gate: `guard-version-check honest lint mypy test arch audit gitleaks`. `guard-version-check` is **fatal** — a stale guard pin fails the build.
- Dev and demo stacks reference the registry `:dev` tag. They previously defaulted to the public GHCR `:latest` (the prod rolling tag) and were overridden at run time with a bare `:local`, so invoking `docker compose` directly silently deployed a different image than the one just built.
- Release builds use the one shared fleet buildx builder (`luxardo-builder`), GC-capped.
- e2e InfluxDB data path moved to tmpfs — every run previously abandoned an anonymous volume.
- Three Boutique devices added to `KASA_COLLECTOR_DEVICE_HOSTS` by hostname. Boutique is cross-subnet, so broadcast discovery cannot reach it and every device there must be explicitly configured.

## Fixes

- **InfluxDB write failures were invisible in metrics.** `send_to_influxdb` logged the error and returned `None`, so `_fetch_counted` counted the device as succeeded. During an outage the per-cycle point reported every device healthy while nothing landed. The outcome now propagates through `process_emeter_data`/`process_sysinfo_data` to the counter. A strip counts as stored only if the parent and every child landed.
- **Discovery pruned a device on a single missed round.** Discovery is a lossy UDP broadcast, so a healthy device can simply fail to answer; it was then dropped from collection for up to a full `DEVICE_DISCOVERY_INTERVAL`. A consecutive-miss counter now gates eviction on `DISCOVERY_MISS_THRESHOLD` rounds, resetting the moment the device answers.
- **Manually configured hosts were attempted once, at startup.** A device listed in `DEVICE_HOSTS` that was down at that moment was never retried — an explicit operator statement that silently did not converge. Reconciliation now runs every discovery cycle.
- **A device missing the startup discovery round waited a full interval.** At startup the registry is empty, so the miss counter cannot protect a device that never got in. A short catch-up pass (`DISCOVERY_CATCH_UP_DELAY`, capped at the discovery interval) closes the window.
- **The `ip` tag held a hostname for manually-configured devices.** The registry keyed on the raw `DEVICE_HOSTS` string, so a tag named `ip` carried a hostname while discovered devices in the same measurement carried an address — the two sites could not be correlated. `get_device()` already resolved the name and connected on that address, so the resolved value existed and was simply never used. The prune guard and manual reconciliation both consult a new configured-entry → resolved-key mapping; without it, re-keying would have pruned the entire Boutique site on the first discovery pass.
- **Health check compared naive datetimes.** `datetime.now()` minus `datetime.fromtimestamp()` were both process-local, so `KASA_COLLECTOR_HEALTH_CHECK_MAX_AGE` was only correct while the container's timezone matched whatever wrote the file. Both sides are now aware UTC.
- **The version probe hid its own failure.** A failed InfluxDB `version()` call logged the identical success line as a clean connect; it now reports "server version unknown".
- **`config.py` logged to the root logger**, bypassing the per-component `KASA_COLLECTOR_LOG_LEVEL_*` routing.
- **The manual-add log line printed the configured hostname under "IP:"** — the same defect as KASACOLLEC-64, in the logs. It now reports the resolved address and the configured entry separately.
- Naive `datetime.now()` replaced with aware UTC across `device_manager`, `poller` and `health/check`. The three display-formatting sites take `.astimezone()` before `strftime`, since a bare `strftime` on an aware UTC value renders UTC verbatim rather than converting.
- 18 broad-except sites adjudicated against `--sweep swallowed-exceptions`: one real fix, one tracked, 16 dispositioned with written reasons.

## Notes

**Post-deploy step (operator, out of band):** `docker buildx rm kasa-builder` on the build host, to reclaim the orphaned per-project cache superseded by the shared `luxardo-builder`.

**No pre-deploy step.** No migration, no backfill, no destructive operation. The `ip` tag value change (KASACOLLEC-64) is forward-only by design — see Schema / Migrations.

- **The KLAP shim is live but currently dormant.** No device in the present inventory requires it — the Boutique plugs report `SMART.KASAPLUG` and already receive v2 from the upstream table, and the five HS300s are on older firmware with the XOR listener open. It is verified against real hardware (a device on the affected path reproduces the upstream authentication failure with the v1 transport) and engages when an IOT-family KLAP device appears. This is a correctness fix for a reachable-but-unused path, not the resolution of an active outage — the handoff brief's "three HS300 strips on fw 1.1.2" did not survive inventory (KASACOLLEC-57); those three devices were simply off the network.
- Guard status files (`.lux*-status.json`) are committed and regenerated by `make status`; the fleet reads them instead of re-running the guards.
