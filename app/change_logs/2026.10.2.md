# 2026.10.2 — 2026-10-10

The container health check now reports what it claims to: healthy only while this run of the collector is storing data. Released documents leave the runtime image, and private network addresses leave the repository's files.

## Issues Closed

- KASACOLLEC-79 — HEALTHCHECK reported healthy with no collection (always with file output off; a previous build's file counted with it on).
- KASACOLLEC-80 — Scrub an org-denylisted hostname, LAN addresses and device names from public history. The commit-message rewrite happened before 2026.10.1 was cut; this release carries the file-content half.

## Features

- **Heartbeat-based health check** (`app/health/heartbeat.py`, `app/health/check.py`). After every emeter cycle that stored at least one device's reading, the poller writes `/tmp/kasa-collector.heartbeat` (inside the container, never on the output mount) with this process's start time. `python -m app.health.check` is healthy only on a heartbeat younger than `KASA_COLLECTOR_HEALTH_CHECK_MAX_AGE` (default 120s) whose writer started no earlier than the current PID 1, with file output on or off. New setting `KASA_COLLECTOR_HEARTBEAT_FILE` (default `/tmp/kasa-collector.heartbeat`).

## Refactors

- `check_recent_data_files()` and `check_process_alive()` are gone: the heartbeat is the one signal. The health check stays stdlib-only, so it never loads the app's settings to answer Docker.

## Schema / Migrations

None. No relational database; InfluxDB measurements, tags and fields are unchanged.

## Infra / Ops

**Pre-deploy: none. Post-deploy: none.** A container shows `starting`, then `healthy` after its first emeter cycle stores data (usually within one `KASA_COLLECTOR_DATA_FETCH_INTERVAL`; the image HEALTHCHECK `start_period` is 30s). A collector that reaches no device now reports **unhealthy** after `KASA_COLLECTOR_HEALTH_CHECK_MAX_AGE`. Before, with file output off, it stayed healthy regardless.

- `.dockerignore` excludes `app/change_logs/` and `app/release_notes/`. The runtime `COPY app` shipped every release document inside the image.
- Guard pins: luxarch 0.278.0 → 0.278.1 (fastapi tenancy only; nothing applies here). luxlint 0.63.1 and luxaudit 0.13.2 unchanged.

## Fixes

- **The HEALTHCHECK could report healthy while nothing was collected.** With `KASA_COLLECTOR_WRITE_TO_FILE` off, `check_process_alive()` returned healthy in both branches. With it on, the check trusted the newest `emeter_*.jsonl` in the output directory, a persistent bind mount, so a file the previous build wrote passed a new build. `make smoke`'s container probe trusts this verdict, and an adversarial pass reproduced smoke passing a container that collected nothing. Each "unhealthy" case in `tests/test_health_check.py` was seen to pass the old check.
- Private LAN addresses in two tests and the 2026.09.1 change log were replaced with documentation-range addresses (`192.0.2.x`, `198.51.100.x`), the same mapping the commit-message scrub used.
- The 2026.10.1 change log no longer cites a pre-scrub commit SHA. `docs/deployment.md` version examples were updated.
