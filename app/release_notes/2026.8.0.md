# 2026.8.0 — 2026-08-02

Kasa Collector is now open source, with a big pass over reliability, shutdown behaviour and its own health reporting.

Surface labels below are this repo's operator surfaces: Collector is the service itself, Dashboards is what you see in Grafana.

> Backfilled 2026-09-07. This release shipped before the project kept release notes, so these were reconstructed afterwards from the issue tracker.

## NEW

- **Kasa Collector is public** `Collector` — The project is now on GitHub, with ready-built images for both Intel and ARM machines. You no longer need to build it yourself.
- **The collector reports on itself** `Dashboards` — Every collection cycle now records how many devices it polled, how many worked, how many failed and how long it took, so you can see the collector's own health next to your energy data.
- **Try it without any hardware** `Collector` — A demo stack runs fake devices end to end, so you can see the dashboards working before pointing it at real plugs.
- **One documentation set** `Collector` — Getting started, configuration, deployment, dashboards, supported devices and troubleshooting now live with the project instead of a separate wiki.

## IMPROVED

- **Stopping the collector is now clean and instant** `Collector` — Stopping the container used to hang for the full shutdown grace period and then be killed. It now finishes its work and exits immediately.
- **Lower CPU use when writing data** `Collector` — Readings are now sent to the database in proper batches rather than one at a time.
- **Reliability** `Collector` — Extensive stability work: stricter internal checks, a much larger test suite, and an automated test that runs the whole pipeline against simulated devices.

## FIXED

- **The setting for dropping unreachable devices did nothing** `Collector` — The option to stop tracking devices that no longer respond was never actually applied. It now works as described.
- **A brief network problem could stall collection** `Collector` — Errors that could never succeed on a retry were retried anyway, using up the retry budget every cycle. Only genuine network problems are retried now.
- **Short database tokens were shown in full at startup** `Collector` — The startup log masks your token, but a token of eight characters or fewer was printed unchanged. Short tokens are now fully masked.
- **Errors were logged without any detail** `Collector` — Unexpected failures logged a single line with no trace of where they came from, which made them hard to diagnose. They now include the full detail.
- **A normal shutdown was logged as an error** `Collector` — Stopping the collector wrote error messages even though nothing was wrong.
- **Odd device names could corrupt the logs and data** `Collector` — A device reporting an unusual name could break log lines and inflate stored data. Names are now cleaned before use.
