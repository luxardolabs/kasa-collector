# 2026.09.0 — 2026-09-06

Your collector now tells you when it can't store data, shows its own health on the dashboards, and picks up devices it previously couldn't reach.

## NEW

- **Collector Health dashboard row** `Dashboards` — See at a glance how your collector itself is doing: how many devices it polled, how many succeeded, how many failed, and how long each cycle took. Poll failures and storage failures turn red the moment either happens.
- **Storage failures are now visible** `Dashboards` — A device can be reachable while the database refuses the write. That used to look like success. It's now counted and shown separately, so an outage can't quietly look healthy.
- **Support for newer power strips** `Collector` — Some strips shipped with firmware that turns off the older local connection method. Your collector can now talk to them, including reading each outlet individually.

## IMPROVED

- **Devices that go away no longer slow everything down** `Collector` — A device that is unplugged or off the network used to be retried on every cycle, dragging collection past its own interval and marking the container unhealthy. Collection cycles that were taking 21–26 seconds against a 15-second interval now finish in about 5.
- **All your devices are collecting** `Collector` — Three devices at the shop were never in the configuration and so were never picked up. They're in now, including a power strip that reports each outlet.
- **Quieter logs** `Collector` — A repeating connection warning that filled the log with over a hundred thousand lines is gone.
- **Reliability** `Collector` — A lot of behind-the-scenes stability work: dependency security updates, stricter internal checks, and cleanups that make future changes safer.

## FIXED

- **The health check could report stale data as fresh** `Collector` — The container's health check compared timestamps in a way that was only correct when the collector's timezone matched the machine that wrote the data. It now compares them correctly regardless.
- **"Connected successfully" could hide a problem** `Collector` — When the collector connected to the database but couldn't read its version, it logged exactly the same success message as a clean connection. It now says the version is unknown, so the difference is visible.
- **Timestamps are unambiguous** `Collector` — Times recorded by the collector are now stored with an explicit timezone. Scheduled-time messages in the log still display in your local time.
